{{- if not .Values.secrets.existingSecret }}
{{- if not .Values.secrets.authSecret }}

WARNING: secrets.authSecret is unset.

TEAMUP_AUTH_SECRET wraps the JWT signing key that TeamUp persists in the
database. Set it now, before anyone signs in:

  secrets:
    authSecret: "$(openssl rand -base64 48)"
{{- end }}
{{- end }}

Two things about TEAMUP_AUTH_SECRET that are easy to learn the hard way:

  * Lose it, and every issued session and refresh token stops verifying.
    Everybody is logged out and cannot be logged back in with old tokens.
    Back it up wherever you keep your other break-glass secrets.
  * Change it, and the same thing happens — it is not a rotation you can do
    casually. Every replica must carry the identical value, which is why it
    lives in one Secret rather than being generated per pod.

{{- $wanted := int .Values.replicaCount }}
{{- if .Values.autoscaling.enabled }}{{ $wanted = int .Values.autoscaling.maxReplicas }}{{ end }}
{{- if gt $wanted 1 }}

  ##################################################################
  #  Running {{ $wanted }} replicas. Messages will go missing.
  ##################################################################

You have set allowMultipleReplicas, so the chart rendered what you asked for.
What that means:

  * The WebSocket hub keeps its state in process — who is connected, which
    channels they are subscribed to, who is in which call. There is no Redis
    pub/sub between replicas and no other channel between them.
  * A message sent by somebody on one replica reaches only the people whose
    sockets are on that same replica. The others never see it, and there is no
    error, no log line and no metric to tell anybody so.
  * Presence splits the same way: each replica shows only its own half of the
    company as online.
  * A reconnect can land on a different replica, so which half of the company
    somebody can hear from changes without warning.

Scale up rather than out: one process serves a few hundred concurrent
sessions.
{{- else }}

Running a single replica, which is what this application supports. The
WebSocket hub is in-process and there is no Redis pub/sub between replicas, so
a second one would silently split the organization in two. See replicaCount in
values.yaml. One process serves a few hundred concurrent sessions; availability
comes from a fast restart, not from a second copy.
{{- end }}

Every replica must carry the identical TEAMUP_AUTH_SECRET — which they do,
since they read the one Secret above.

Health endpoints:

  /healthz  liveness  — the process is up
  /readyz   readiness — PostgreSQL, Redis, object storage and, when
                        TEAMUP_LIVEKIT_URL names an HTTP endpoint, LiveKit

A pod that cannot reach one of those stays out of the Service until it can,
rather than answering 500 to uploads and calls behind a rollout that looks
green.
